# Web 工程开发说明

`index.html` 和 `src/main.ts` 是唯一构建入口，启动后直接加载新版前端。`pnpm run build` 的产物写入 `internal/webui/dist`，随 Go 二进制交付。

## 代码边界

- `src/frontends/modern/`：唯一的前端，包含启动、路由、布局、组件、业务功能、接口类型、样式和文案。`@modern/` 指向此目录。
- `src/shared/`：HTTP 客户端、基础协议和语言标识。`@shared/` 指向此目录。页面响应 DTO、业务查询编排和组件不放在这里。

前端可依赖 shared；shared 不能反向引用前端或启动入口。现有 ESLint 命令检查静态导入、导出、动态导入和资源 glob 的路径边界。入口和 shared 不导入前端样式。

## 当前实现范围

新版目前提供 Coral Anchor 品牌框架：位于分隔线中部的侧栏折叠控件、移动端导航抽屉、宽工作区。顶栏是各页共用的固定结构，左侧为当前页标题，随后是数据更新时间与刷新，竖线之后依次是导入密钥入口、明暗模式、语言和退出。页面导航按“工作区”“运行观测”和“系统”直接展示，不通过二级 Tab 进入观测页面。

`app/navigation.ts` 统一描述导航入口。`internal/webui/page_routes.json` 保存全部 13 个页面地址，服务端与前端读取同一份清单。所有页面返回同一个 HTML 入口；`/monitor` 跳转到用量页面。

新版已提供总览、分组列表与详情、访问密钥、模型管理、请求日志、用量统计、运行健康和全局设置。总览围绕客户端接入配置、请求趋势、订阅账号额度和健康待办组织内容；客户端选择与路由检查独立。`/monitor/inspector` 重定向到首页的路由检查区，保留检查参数；`/import` 重定向到分组页的导入入口，选择新建分组或为已有分组添加凭据。路由加载失败时提供刷新重试。

分组工作区采用双行列表：分组与渠道、凭据总数及状态进度条、模型数量及计价倍率、近 24 小时请求与用量、启停与行内权重。支持本地搜索、渠道与运行视图筛选、排序、复制地址和就地展开完整模型。完整轻量快照一次读取，默认每页 20 条，可选 50 / 100；表头与底部分页固定，仅内容区滚动。基础编辑在分组详情中完成，模型和高级配置使用独立侧栏。API 密钥与订阅账号分别提供卡片、筛选、分页、详情及批量操作；订阅账号同步状态相互独立。

模型页以请求模型卡片展示上游来源、关联分组及计价规则。日志页支持游标分页、详情和字段快捷筛选；用量页提供请求成功/失败、输入/输出 Token、缓存与费用趋势及来源排行。健康页和首页待办共用 `/api/health`，报告返回完整异常明细，筛选与分页在浏览器中完成，不限制后端报告数量。业务数据继续由后端 principal 权限合同约束。

明暗模式和语言是本地浏览器偏好，登录页也可调整；全局设置页沿用管理员访问限制。侧栏收起状态使用 `gpt-load.modern.sidebar-collapsed`，所有界面偏好不读写服务端配置。新版品牌组件根据实际明暗状态变化触发动画，也处理侧栏折叠和展开；遵守减少动效偏好。

侧栏底部以两行两列展示外链：首行为使用文档、赞助支持，次行为 GitHub、Telegram。GitHub 使用官方 Octicons 标识。分隔线下显示版本号和管理员更新检查入口；设置页的系统信息区也提供更新检查。版本来自现有 `/health`，新版本只在用户点击时通过 `/api/system/update` 检查，传 `force=true` 并使用当前已验证的平台管理员会话。新版统一持有检查状态，侧栏与设置页共享结果，不重复检查；非平台管理员不查询管理员更新接口。

新版页面可以独立设计展示 DTO、聚合查询及管理接口。`modern/api/` 为其独立接口代码目录。分组展示使用 `/api/modern/groups`，当前页用量通过 `/api/modern/groups/usage` 批量读取，每次最多 100 个分组，复用后端精确时间窗口及最终请求归属。边界明细查询使用分组与完成时间联合索引，避免逐组扫描或计算完整排行榜。凭据展示使用 `/api/modern/groups/:group_id/credentials` 和其详情接口，按当前页补充活动数据。启停与编辑继续调用既有管理接口，旧接口合同及核心流程、数据面行为保持稳定。

## 登录与权限

控制台登录交给 Casdoor（OpenID Connect），由网关后端完成。登录页（`modern/features/auth/`）只有一个“使用 EchoJoy 账号登录”按钮，点击后跳转 `/auth/login?redirect=<站内路径>`；`redirect` 只接受站内已知受保护路径，保留查询和 hash。Casdoor 认证后回到网关 `/auth/callback`，再由网关跳回 `redirect`。网关回调失败时回到 `/login?error=no_access`（账号不存在、被禁用或不属于任何团队且不是平台管理员）或 `/login?error=login_failed`（其他失败），登录页只识别这两个取值并显示对应提示。

会话只由 httpOnly cookie `gl_session` 承载，前端不保存任何密钥，也不读写 localStorage 或 sessionStorage 中的凭据。请求以 `credentials: 'same-origin'` 自动带上 cookie。前端通过 `GET /api/auth/session` 得知登录状态和身份，响应为 `{user, teams, platform, admin_teams}`：`user` 含 `id`、`name`、`display_name`、`email`；`teams` 是所属团队；`platform` 表示平台管理员；`admin_teams` 是本人担任管理员的团队。

刷新页面后先请求一次会话，再挂载工作区和业务组件；并发恢复只发出一次请求。网络与响应异常显示重试入口，不清除会话状态。收到 401 时清空身份、取消并清除新版查询缓存，返回登录页；权限拒绝的 403 不误登出。

`app/navigation.ts` 的 `adminOnly` 同时约束路由、侧栏和快捷导航，只有平台管理员（`platform`）能进入，其他用户访问这些路径时回退到总览；团队管理员和成员只能进入其余入口，数据范围仍由后端按团队和本人收窄。顶栏显示当前用户及所属团队，并标出本人担任管理员的团队。

退出时先离开当前页面（离开受阻时保留会话），再 `POST /auth/logout`：网关删除会话并清除 cookie，返回 Casdoor 登出地址 `redirect_url`；前端清空本地身份和查询缓存后跳转该地址，由 Casdoor 结束单点登录会话并回到 `/login`。

HTTP 客户端按请求捕获会话版本；身份已切换或请求已取消时，迟到的 401 不清除新会话。会话恢复也检查版本和取消状态，防止退出后被旧响应重新登录。共享 HTTP 层提供基础请求合同；服务端继续负责身份认证与接口权限。

## 验证

前端使用现有 lint、format、type-check 和 build；最终运行仓库 `make check`。不增加前端测试、浏览器验收或本地 race。
